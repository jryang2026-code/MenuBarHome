## 我们是谁

MenuBarHome（旧名 MenuBarMijia，GitHub `jryang2026-code/MenuBarHome`）：macOS 菜单栏（Swift 6 / AppKit + SwiftUI，自研 NSPanel 面板，常规 / 液态玻璃两套主题）+ Windows 11 托盘（Tauri v2 / TypeScript，Fluent 2 双悬浮岛）双端智能家居控制中心。数据源：米家云端直连（扫码登录、MIoT spec 合成设备卡、局域网 miIO 优先）与 Home Assistant（WebSocket）。另有 Raycast 扩展、本地 CLI、MCP 服务（只读快照 + `menumijia://` URL 控制）、本地口令解析 + 自选大模型助手、习惯推荐、状态自动化、摄像机（go2rtc / 私有 P2P 桥）、Ed25519 验签自更新。

先读（只读，几分钟即可）：

## 方法要求（硬性）

1. **扒三层**：第一层看 README/文档/截图 → 第二层浅克隆读核心源码 → 第三层追到关键机制的具体实现（状态机、协议、调度、动画参数、错误处理），讲清"为什么这样做"。不能只停在功能列表。
2. 克隆位置：`~/.cache/mbh-research-clones/<owner>__<repo>`，用 `git clone --depth 1 --filter=blob:none`。已存在就复用（别的子任务可能克隆过）。**只读源码，不运行克隆下来的任何脚本、构建或安装命令。** 不在本仓库内克隆、不改本仓库除你的报告文件以外的任何文件，不 commit、不 push、不开 issue/PR。
3. 证据标注：每条结论标 **【源码】**（附 `repo:path:行号` 或 GitHub 永久链接）、**【文档】**（附 URL）、**【检索】**（只看了搜索摘要/评论，附 URL 和日期）、**【推断】**（你的判断）。分不清就降级标注，**禁止编造链接、行号、星数或用户评价**。查不到就写"未查到"。
4. 每个对标点都要落到我们：对照我们仓库的具体文件（用 `grep` 定位，Swift/Rust 无 LSP），说清"我们现在怎么做 / 差在哪 / 怎么借鉴 / 成本"。
5. 维度覆盖（按你的主题取舍）：功能实现、系统效率（轮询/推送/内存/电量/启动）、内部逻辑（状态模型、错误恢复、并发）、UX、UI 视觉、动效实现（具体曲线/时长/弹簧参数/API）、设备适配覆盖面、不同厂商不同接口的处理方式、插件化/扩展架构、安全与隐私。
6. 鼓励天马行空，但单列在「设想」一节，和有证据的建议分开。
