## 0. 核心裁决（直报体）

**一句话诊断**：第一波 10 份报告的工程源码深度达到一线水准，但整体陷入了严重的**「工程师自我感动与功能通胀综合征」**。MenuBarHome 当下最真实的商业水位是：**生产代码已膨胀至 22.4 万行（测试 19.1 万行）、48 小时内狂合 40+ PR，但迁仓后的新仓仅有 47★、三版总安装包下载仅 378 次（其中 Windows 占 39.9%）、`Discussions` 为 0、且连自家 `README.md` 都还在把 Windows 写成残血版**。在「招牌被拆、门锁生锈、四成用户被 SmartScreen 劝退、新用户搜不到入口」的当下，第一波部分方案却在规划四层插件市场、`mbh-wasm-host` WASM/WIT 沙箱、MCP Hub + `goja` `run_code`、GPU 屏幕采色、380px 平面图拖拽抛送、刘海胶囊与虚拟 HAP 桥——这是典型的**用重工程幻想逃避分发、信任与核心体验止血**。

**五项审校总结论**：
1. **证据复核**：`02-community-feedback.md` 的核心数字（39.9% Windows 占比、全部 27 个抽查 Issue/PR、原话与竞品实测）**经独立抽检 100% 属实**；纠偏 **2 处小统计误差**（Open Issues 实为 28 非 30；无直接讨论渠道实为 15 个非 14 个）与 **3 处「直接评价 vs 同赛道推断」结论滑坡**。
2. **反膨胀裁决**：对 `05`/`08`/`09`（含横向报告）共 **24 项**主要产品设想逐一划红线——仅 **7 项**准入主核，**7 项**锁死为可选外部插件/默认关闭扩展，**10 项**明确降级至 P3 或直接否决（其中 **虚拟 HAP/Matter 桥直接违背本仓 `.out-of-scope` 红线，必须一票否决**）。
3. **灵魂拷问答案**：桌面端绝不是去和「喊小爱」拼单次开关灯，而是死磕「**静音精准操控 + 桌面置顶盯摄像头 + 电脑上下文自动联动与状态栈无痕还原 + 零凭据工作流集成**」四张牌；Windows 平权与免费开源签名（`#12` SignPath）必须提到 **绝对 P0**。
4. **排序纠偏**：给出基于四维 ROI 的 P0–P3 客观分层模型，列出 **5 项必须后置/否决的高大上伪优先项** 与 **5 项看似极小却转化爆表的 P0/P1 纠偏项**。
5. **打回判定**：**无需打回第一波重跑**（事实底座足够扎实），但须由总指挥在综合路线图时直接补齐第一波遗漏的 **4 项产品盲区**（获客漏斗与冷启动动作、版本发布与文档同步纪律、`#12` 免费签名与 `#11` 付费签名解绑、核心用户画像摸底）。

### 1.2 「直接评价」vs「同赛道推断」边界审计（3 处结论滑坡警示）

`02-community-feedback.md` 的整体分区意识值得肯定（正文严格分 Part A / Part B），但在**向综合决策转化时仍出现了 3 处危险滑坡**，若不拦住会直接带偏路线图：

1. **滑坡 1：Part A 夹带竞品衍生信号，被下游当成「自研桥接」依据**
   - `02` A3 第 3 行将 `iPocket-APP/MijiaLAN`（187★）直接放入 Part A 表格并下结论「证明免 HA 将米家桥进苹果家庭是极强刚需」。事实边界应是：**只有 GH#190 一条小红书评论属于 MenuBarHome 直接反馈**，`MijiaLAN` 是独立单点工具的市场信号。结果 `08` 报告顺势将「Virtual HAP / Matter Bridge」写进 Phase 3 路线图，**直接撞穿了本仓已接受的 `.out-of-scope/direct-matter-bridge.md` 与 `always-on-bridge-and-mobile-app.md` 红线**！
2. **滑坡 2：结论区把 Part B 竞品呼声包装成 MenuBarHome 的「高 ROI 缺口」**
   - `02` §2 第 3 条力推的「Stream Deck / SSE 事件流、桌面悬浮小卡、AI MCP 按设备三级权限、根据 Wi-Fi 自动切家」，**100% 源自 Part B 竞品社区（Itsyhome / HomeBar / MiHome-Windows）**；在 MenuBarHome 自身 126 个 Issue（含外部建单和全网搬运）中**零次出现**。它们属于「有参考价值的同赛道增量灵感（P1/P2）」，绝不能与「0 设备流失」「未签名劝退」「Windows 体验差距」等直接实证痛点混为一谈。
3. **滑坡 3：外部评价严重滞后于 `HEAD`，且自家文档正在主动误导用户和调研员**
   - 外部直接吐槽（「像 2345 网址导航」「空调不能用」「高风险开关灯关不掉」「Windows 没趋势图没多账号」）全部发生在 **v1.1.x（2026-10 月底～11 月初）**，其中绝大多数已在 v1.2–v1.4 解决。

## 二、「反膨胀」克制性体检：从 24 项设想中划出铁血红线

### 2.1 MenuBarHome 轻量化四条宪法（防止变成「低配版 Home Assistant」）

在逐项审判前，必须明确 MenuBarHome 绝不能丢的灵魂：
1. **形态宪法**：它是**「桌边 2 秒控家 + 电脑上下文伴生控制中心」**，不是 24/7 常驻服务器，不是多页全屏仪表盘，不是手机 App 替代品。
2. **认知与资源宪法**：主面板 380–440px 窄窗必须在 **3 秒内扫完首屏**；后台关窗后遵守近零唤醒、macOS ≤25MB、Windows 渐进瘦身红线。
3. **生态与安全宪法**：内置源**只死守米家直连 + Home Assistant 两座大山**（+ Demo）；所有写门、危险分级、锁屏拦截、凭据库永归宿主；绝不为凑功能去申请吓跑普通用户的「屏幕录制」等高敏权限。
4. **双端维护税宪法**：本仓当前为 Swift（11.5 万行）+ TS/Rust（10.8 万行）完全双轨平行开发。**任何不能显著拉升留存或护城河、却要双端各写一套状态机和 UI 的主核功能，一律否决！**

### 拷问 1：「用了两天卸载了，不如直接喊小爱 / 手机方便」（X `@tuolaji2024`）—— 桌面端不可替代的场景杀手锏到底是什么？

**先说大实话**：在独居、能随时出声、只需简单「开/关一盏灯」的场景下，喊小爱同学**确实比任何电脑软件都快**。任何试图在「单次开关灯便利性」上与智能音箱硬碰硬的宣传，都是拿短板碰长板。

MenuBarHome 能让用户**绝对卸不掉的 4 个不可替代杀手锏**（手机和音箱永远做不到或极难做好）：
1. **「静音 + 精准微调」场景（开会、深夜、连麦、打游戏）**：V2EX `#1225988` 大量吐槽小爱「耳背」，而深夜怕吵醒家人、语音会议静音、游戏关键团战时根本不能喊、也不能低头解锁手机。`⌥M` + 拼音首字母 + 方向键，或**单设备全局热键 1 步盲操**，零出声、零低头、精准到 1% 亮度 / 0.5°C 温度。
2. **「边工作边盯监控」场景（桌面置顶画中画 + 门铃弹窗 + 顺手开灯）**：小爱没屏、手机会息屏锁屏。电脑右上角常驻一块免 HA 直连的米家摄像头置顶小窗，门铃一响自动弹出还能在小窗里顺手点亮玄关灯——这是全中文社区讨论热度第一、但小米官方长期拒绝提供的能力，也是 MenuBarHome 已经遥遥领先竞品（如 845★ 仍无摄像头的 `MiHome-Windows`）的王炸！
3. **「电脑上下文自动联动 + 状态栈无痕还原」场景（甚至不用手动点）**：电脑天然知道你**正在开摄像头/开麦开会、插上外接显示器、进入全屏游戏/观影、锁屏离开**。只要把「开会自动开补光灯 + 暂停扫地机，**散会精确恢复开会前原状**」在双端做透，它就从「遥控器」进化为「办公桌环境管家」——这是手机 App 和音箱在物理信息源上**完全不可能拥有**的维度优势。
4. **「极客桌面工作流闭环」场景**：写代码、跑 Claude/Cursor Agent、按 Stream Deck 时通过零凭据 CLI / Raycast / MCP 顺手查状态与控家。

> **产品路线反推**：对外定位与首屏演示必须立刻从笼统的「不用掏手机控米家」升级为**「静音办公控家 · 桌面盯监控 · 开会/锁屏自动布光」**三板斧；凡是不强化这 4 个场景的新需求一律靠边站。

### 拷问 2：「像 2345 网址导航 / AI 布局一套样」（X `@itshanrw` / `@jasmine961203` / `@TimeStudioApps`）—— 如何从根上摆脱工具感/堆砌感，做到 Raycast / Apple Control Center / Linear 级克制美学？

**毒舌诊断**：换上 macOS 26 Liquid Glass 或 Fluent 2 材质**治不了「AI 味和 2345 导航感」**！社区一眼认出「AI 布局」的真正病根有四个，且目前仍在潜伏复发风险中：
1. **病根 1：首屏「功能全陈列症」**—— 摘要行 + 通知堆叠 + 为你推荐 + 快捷场景胶囊 + 房间 Tab + 搜索栏 + 设备网格 + 底部状态栏，380px 窄窗里垂直塞进 6–8 层横条，信息密度爆炸且每层都在抢视线。第一波 `09` 还想再加一层「此刻 (Now)」动态焦点带，这是往刚消肿的伤口上继续贴膏药！
2. **病根 2：廉价色彩噪音**—— 缺乏统一克制的中性基底。Apple Control Center、Raycast、Linear 的高级感全部来自 **「90% 中性玻璃/黑白灰 + 仅活跃态主语义色（灯暖黄/空调冷蓝）+ 唯一告警红」**；而 Windows 版目前连系统强调色都没读，仍在硬编码 `#60cdff/#005fb8`！
3. **病根 3：控件层级平权化**—— 关着的设备和开着的设备占同等视觉权重、高频调光还要点进大抽屉、常用 4 台设备和吃灰的路由器混在同级视觉噪音里。

**根治药方（5 条不可妥协的美学减法铁律）**：
1. **首屏强制 ≤3 视觉层级**：默认展开状态仅保留 **① 顶部融合搜索/口令栏 → ② 常用/当前房设备卡片网格 → ③ 仅在有异常或活动时才浮现的 1 行条件态摘要**。`For You` 推荐与快捷场景条必须收敛/折叠为单槽或默认收起，严禁 6 层水平区块同时堆叠。
2. **「关态退让 + 原地微控」**：学习 `lovelace-mushroom`（关机自动隐藏操作行）与 `Bubble-Card`（1% 钳位 + 原地变形子滑块），让关闭态卡片极低存在感、开启态瞬间点亮语义光晕，80% 高频调光/调温在卡片原地 1 步完成。
3. **色彩与系统材质绝对原生**：守住 90% 中性面 + 活跃色 + 唯一告警红；Windows 端接入真实 `UISettings` 系统强调色、区分 `SystemUsesLightTheme` 托盘图标对比度、设置窗上真 Mica，告别硬编码蓝色与粗糙滚动条。
4. **窗口交互零打扰升级**：macOS 切 `.nonactivatingPanel` + `acceptsFirstMouse` + 顶边锚定 200ms 平滑高度动画；Windows 补 `WS_EX_TOOLWINDOW` + `DWMWA_CLOAK` + 120Hz `CSS linear()` 弹簧曲线。
5. **全界面清零工程师黑话**：把所有面客文案里的「Miot 直连」「英文型号码」替换为中文产品名与自然状态词（`MiHome-Windows #35` 同款痛点）。
