# 功能概览与双端对照

[← 返回 README](../README.zh-CN.md)

MenuBarHome 的 macOS 版本采用 Swift 6 原生开发，Windows 11 版本基于 Tauri v2 / TypeScript 独立实现。两端均经过共享测试集（`Tests/Fixtures/`）断言基础协议的一致性，但系统级能力存在平台差异。

| **米家云端扫码直连** | ✅ 支持 | ✅ 支持 | 手机米家 App 扫码登录，双端均支持同时登录多个小米账号及中/欧/美/俄/新加坡多区域服务器；同时加载自有家庭与被分享给该账号的家庭。双端均支持符合条件的 Wi-Fi 设备（`pid` 属于 `[0, 8, 12, 23]`）局域网 miIO UDP 54321 优先直连与明确写回执（旧款非 MIoT 局域网设备自动回退云端）、为手动写入预留云端限流配额并指数退避、`status=all` 规格索引配合 `Shared/specPatches.json` 与官方 `multiLanguage` 翻译缓存，以及设备身份墓碑与注册表备份（`CanonicalDeviceRegistry`）；macOS 还会对云端离线设备做只读局域网可达性探测提示 |

| **键盘搜索与设备控制** | ✅ 支持 | ✅ 支持 | 按设备名、房间或拼音首字母（如 `sftd`）搜索；方向键选择与调节，回车切换设备或执行口令，双端均支持 `Tab` 轮转房间标签及 `⌘K` / `Ctrl+K` 展开或收起「快捷」抽屉；同房间同品类达到 2 台及以上可控设备会自动生成房间分组胶囊。macOS 采用不抢占应用焦点的面板，仅在文本输入时按需激活 |
| **全局快捷键呼出** | ✅ `⌥M`（支持自定义） | ✅ `Alt+M`（支持自定义） | 双端均支持主面板快捷键录制与冲突检测，以及最多 8 组单设备、场景、快捷动作或氛围的自定义全局快捷键绑定（含冲突检测、锁屏拦截与高风险确认）；macOS 附带不抢焦点的 HUD 提示 |
| **语音控制方式** | ✅ 菜单栏按住 / 快捷键按住 / 免提 | ⚠️ 仅免提听写 | macOS 支持系统原生听写与按住说话；Windows 使用 WebView 听写，支持面板聚焦时 `Ctrl+M` 切换语音听写（`Esc` 立即取消）、基于家中词表的同音热词后纠偏（`speechPostCorrection.ts`），以及语音提交走变更预览确认 |
| **本地口令解析** | ✅ 支持 | ✅ 支持 | 开关、调光、色温、调温、风扇无级百分比（`1–100%`）与档位、窗帘/开合设备位置（`0–100%`，车库门/开窗器/晾衣架强制高风险确认）、延时与只读状态查询均在本地解析，支持拼音/首字母/同音字兜底匹配与三路未命中诊断（`unknownDevice` / `unsupportedAction` / `unrecognizedPhrasing`）；涉及 2 台及以上设备或任意高风险设备的指令执行前内联展示变更预览；macOS 支持连续 3 次一致命中后 0ms 习惯短语直达（撤销同步回滚） |
| **自选 AI 决策助手** | ✅ 支持 | ✅ 支持 | 可接入 Jev、DeepSeek、千问、GLM、Ollama 或自定义端点，API Key 按服务商独立分槽保存，支持 3,600 token 动态目录裁剪、`response_format` JSON Schema 及 400/422 自动回退重试、风扇百分比（`fan_percentage`）与窗帘（`.cover`）控制，以及双端受控布尔/枚举**桌面情境感知**（`inMeeting` / `externalDisplayConnected` / `focusActive` / `lateNightWork` / `mediaPlaying`，遵循 ADR-0015 绝不采集窗口名、日历标题或 Wi-Fi SSID）。在开启 Apple Intelligence 的 macOS 26+ 上，设置 → AI 显性展示 **Apple Foundation Models** 本机模型状态卡，支持一键设为默认、免 API Key 测试连接、本机主动建议（4,096 token 窗口内）及「不确定时先问我」开关 |
| **「猜你想控」主动推荐** | ✅ 最多 4 项 | ✅ 最多 4 项 | 手动点卡片也按时段与工作日/周末计入习惯记忆，带 14 天半衰期衰减与动作序列预测（撤销同步回滚，详见 [ADR-0009](adr/0009-habit-ranking-algorithm.md)），并融合双端受控枚举桌面情境信号（如会议中补光/静音、深夜办公护眼）；本地推荐立即显示，已配置的云端大模型或 macOS 26+ 本机 Foundation Models 在后台刷新。可执行动作不足四项时显示实际数量。 |
| **顶部快捷动作与场景栏** | ✅ 3 个动作 | ✅ 3 个动作 | 与「猜你想控」统一折叠在 **快捷** 胶囊里（`⌘K` / `Ctrl+K`，新装默认收起）。双端均提供 全屋关灯 / 柔和夜灯 / 关温控风扇（有对应设备时显示；Windows 演示模式用四个示例动作），并追加 Home Assistant / 米家云端手动场景与本地 **氛围**（最多保存 32 个房间设备状态快照，可通过快捷区或自定义快捷键恢复）。macOS 下动作与场景合计不超过四项时等宽铺满，更多则支持普通鼠标滚轮横向滚动。 |
| **批量全关与即刻撤销** | ✅ 支持 | ✅ 支持 | 长按 0.6 秒触发全关（macOS 高风险面板指针操作亦采用 0.65 秒长按或右滑确认手势）；插座、扫地机、摄像机与窗帘开合类默认不参与，可调整；操作可撤销时提供 10–15 秒横幅；双端均对滑条与多通道开关写入做了合并节流 |
| **状态自动化** | ✅ 支持 | ⚠️ 部分支持 | macOS 支持定时（`scheduledTime`）、持续时长（`supportsLasting`）、锁屏、休眠/唤醒、外接显示器、摄像头/麦克风占用、电源与电量、Wi-Fi、专注模式、日历、深夜使用及前台应用触发（内置一键「开会」「观影」模板与生产事件源守卫；规则默认为空且不自动开启）。Windows 已覆盖锁屏离开/解锁回来、电源与电量（`GetSystemPowerStatus`，10 秒轮询）、外接显示器（`QueryDisplayConfig`）、休眠与息屏（`PowerRegisterSuspendResumeNotification` / `GUID_CONSOLE_DISPLAY_STATE`）、摄像头/麦克风占用（`CapabilityAccessManager` 注册表变更监听，自动排除 MenuBarHome / `go2rtc` 自身）、专注/全屏/演示/勿扰状态（`SHQueryUserNotificationState` 配合 `EVENT_SYSTEM_FOREGROUND` 与 10 秒兜底采样）、Wi-Fi 连接/离开（含 Wi-Fi 条件）、深夜用机、定时与传感器阈值；双端均支持 LIFO 上下文栈恢复（`AutomationContextStack`，最多 32 帧 / 12 小时有效期）；日历、合盖休眠与前台应用暂无 Windows 事件源 |
| **系统快捷指令集成** | ✅ 支持 (7 个动作) | — 暂不支持 | 提供设备切换、执行场景、一句话控制、查询温湿度、调亮度（0–100%）、调色温（1000–20000K）、执行快捷动作 7 项 App Intents（同一动作可有多种参数组合）。所有参数化动作复用 URL 控制链路，能力写入门、锁屏拦截与高风险二次确认照旧生效。开启「在系统搜索（Spotlight）里找到设备、房间与场景」后（默认关闭，只索引名称，不含 ID、地址或令牌，退出账号或关闭开关即清空），设备、房间与场景会出现在系统 Spotlight；专注模式过滤条件会在直接切换不同专注模式时同步对账静音配置文件，但安全告警与门铃绝不会被静音 |
| **URL Scheme 控制** | ✅ 支持 | ✅ 支持 | `menumijia://`（及等价别名 `menubarhome://`）支持 `toggle`、`power`、`brightness`、`color-temp`、`temperature`、`fan`、`cover-position`、`volume`、`mute`、`media-play-pause`、`scene`、`ask`、`focus`；调用默认需确认（车库门与开窗器即使设 0% 也强制高风险确认），可在设置中允许直接执行；Windows 通过单实例转发交给运行中的托盘程序处理 |
| **Raycast 扩展、本地 CLI 与 MCP 服务** | ✅ 支持 | ✅ 支持 | `raycast/`、`scripts/mijia` 与 `scripts/mijia-mcp`（随包打包进 macOS `.app/Contents/Resources/cli/` 与 Windows Tauri `cli/` 资源目录，设置页「复制配置」自动解析真实路径，零占位符）只读 `raycast-snapshot.json` 并经 `menumijia://` 控制，不持有任何凭据。MCP Server 2.0 暴露 5 项只读资源（`mijia://status`、`mijia://devices`、`mijia://scenes`、`mijia://sensors`、`mijia://automations`）、17 个工具（5 只读 + 12 控制，新增窗帘位置与媒体音量/静音/播放暂停，`ask_home` 标 `openWorldHint: true`，严格 `--read-only`）以及 `mijia doctor` / `mijia mcp --doctor` 一行健康自检；响应自动剥离 `bridgeToken` 与系统自由文本，高风险二次确认与锁屏拦截仍在应用内执行 |
| **传感器历史折线图** | ✅ 24h / 7d 趋势 | ✅ 24h / 7d 趋势 | 双端均支持在传感器卡片直接悬停看 24 小时迷你曲线，以及切换温度、湿度、PM2.5 或光照的完整 24h / 7d 趋势图（本地分桶 + 米家 / HA 历史回填）；安全与定时通知均支持锁屏保护的「立即关闭」「查看」「立即补执行」交互按钮 |
| **插座电量统计** | ✅ 支持 | ✅ 支持 | 双端均按插座上报的真实累计电量增量记录逐日账本并支持电费估算，无数据不凭空估算 |
| **米家空净 / 新风机 / 加湿器** | ✅ 支持 | ✅ 支持 | 双端合成 `air-purifier`、`air-fresh`、`humidifier` 规格：PM2.5 / 空气质量 / 温湿度 / 滤芯余量，风速 1–100% 联动最爱挡位 |
| **冰箱与厨房家电** | ✅ 支持 | ✅ 支持 | 冰箱按冷藏、冷冻分室显示当前与目标温度，支持 手动 / 智能 / 假日 / 速冷 / 速冻 模式；电水壶、饮水机、电饭煲、空气炸锅、烤箱、微波炉、养生壶显示工作状态、温度与剩余分钟数，带 `start-cook` / `pause` 动作的机型可直接启停 |
| **热水器** | ✅ 支持 | ✅ 支持 | 米家热水器合成为通用家电卡：电源、模式、目标温度（范围与步长取自规格）、状态、故障条、剩余时间与无参的开始 / 暂停动作，规格里有才显示；当前水温作为主读数。打开或调高温度需确认，关闭直接执行；热水器默认不参与「全关」 |
| **HA 加湿器、热水器与阀门** | ✅ 支持 | ✅ 支持 | Home Assistant 通道合成 `humidifier`（电源、模式、目标湿度与自带湿度读数）、`water_heater`（复用通用家电卡，打开或调高温度需确认）与 `valve`（开 / 关，打开水阀或燃气阀需确认）。未被主卡片认领的 `switch`、`select`、`number`、`button`、`sensor`、`binary_sensor` 实体进入「更多设置」，支持乐观写入（macOS 同时提供撤销）；`text` 实体跳过 |
| **浴霸与油烟机** | ✅ 支持 | ✅ 支持 | 米家浴霸把 PTC 暖风、风量、室温读数与灯光合成一张家电卡：电源、目标温度、规格里的模式列表、风量、灯光开关、室温与湿度；油烟机把排风电源、风量与照明合成一张卡。副服务的灯只作为卡内开关，不再单独成卡。规格里没有的控件不显示 |
| **洗衣机、烘干机与洗碗机** | ✅ 支持 | ✅ 支持 | `washer`、`dryer`、`clothes-dryer`、`dishwasher` 规格合成为通用家电卡：卡片主区显示程序、洗涤阶段与剩余分钟（如「洗涤中 · 剩余 42 分」），另有故障条与无参的开始 / 暂停 / 停止。程序多达二十几项时在抽屉里横向滚动，不平铺成一片。开始需再确认，暂停与停止直接执行；规格里带参数的动作直接忽略，不会让整张卡报错 |
| **除湿机 / 水暖毯 / 香氛机 / 音箱** | ✅ 支持 | ✅ 支持 | 除湿机合成为风扇卡，按其上报的模式列表切换并读取自身温湿度，水暖毯合成为温控卡，香氛机作为可开关插座，双端音箱卡均支持音量、静音、播放状态、正在播放（`MediaPlaybackState` + 防回跳拖拽进度条）、睡眠模式及小爱音箱「播报 / 指令」文本控制 |
| **门锁与人体、环境传感器** | ✅ 只读卡片 | ✅ 只读卡片 | 门锁显示电量。读到 `door-state` 或 Home Assistant 的 `lock` 实体时展示已上锁、已开锁、虚掩或卡住；没有可靠状态时显示「锁状态未知」，不再固定写成「守护中」。人体移动/存在、门窗磁、水浸、光照与空气质量监测合成为传感器卡片；MIoT 不开放远程开锁，门锁只作状态展示。macOS 上，米家网关、路由器、中继器在有可用规格项时改为通用卡片（只读或低风险写入），没有规格或没有可用项时才进入「未显示设备」列表 |
| **通用兜底卡片** | ✅ 支持 | ✅ 支持 | 米家规格里没有专用类型、但仍有可用控件或读数的设备显示一张通用卡：名称与房间、最多两个关键读数、一个低风险主开关，其余控件进入「更多设置」（MIoT `television` 与 `stb` 机型双端均已合成专属电视卡片）；只读设备明确标注「只读」。门锁、加热类与路由器配置默认只读，放开次要写入需二次确认；通用卡默认不参与「全关」与助手批量指令。Windows 的「更多设置」写入即时生效，但不提供撤销 |
