# 编排者裁决（优先于设计稿与审查建议）

依据：review-architecture.md、review-ui.md，以及编排者回到代码的核对（HEAD 936b6f03）。

## 产品与架构

1. 用户语言用「连接」「功能」「设备类型」，页面叫「功能管理」。代码和计划可以继续说模块。不做第三方代码插件，不做插件市场。
2. 设备类型开关是显示和资源偏好，不是安全边界。
3. 安全信号独立于设备类型开关。对应的安全提醒开启时，传感器、门锁、阀门、插座、空调等信号来源继续读取并进入告警评估，只是不进入面板、搜索、AI 目录和控制入口。要停止某类提醒，用户到「安全与提醒」单独关闭。界面必须如实说明「只用灯和开关」时，为了提醒仍会读取部分设备。双端黄金语料固定断言：关闭传感器类型后漏水告警仍触发。
4. 目标设备不在当前可用集合时，宿主统一显式拒绝并零写入，文案区分「该设备类型已关闭」和「设备不存在」。不能依赖确认门对未知设备返回 false 后的下游失败。
5. 平台场景和脚本由用户手动启动时继续可用，只提示「可能控制已隐藏的设备」。不做场景目标提取，不因设备类型裁剪批量暂停场景栏。高风险确认语义不变。
6. 定时、启用的自动化、快捷动作引用被关闭对象时，不能静默失效。显示受影响项，用户选择「暂停这些项并关闭」或「取消」。暂停项保留，重新开启时重验目标，过期定时进入错过流程。
7. 老用户判定以既有设置标记为主，凭据和数据为辅。身份读取失败或不确定时沿用旧启动逻辑，不写成功状态，迁移版本化且可重试。
8. 摄像机助手继续随 App 提供，本轮不改分发方式，不做按需下载或「移除组件」。先做懒启动和停用后彻底回收。清理运行时上游下载和任意路径执行另开决策。
9. 普通 ID 用清单映射的值类型加穷尽校验。品牌类型和私有构造只留给安全对象，例如已校验端点、已验证资源、回收句柄。
10. macOS 双实例不作为支持场景，但迁移和清理写入采用读取、合并、写回，并记录冲突诊断。

## 工作包调整

- P1 拆成 P1a（清单、双端解析、门禁、文档映射，零行为）和 P1b（引用判决与黄金语料，判决引擎按端随首个消费者落地）。
- P2b 依赖 P2a，共用 activeBackends 开关输入。Windows 拆成 TS 停用与写入门，以及 Rust 可取消连接两个 PR。
- P4 拆成 P4a（首次选平台，含未连接不自动扫局域网，走 PR，可早于设备类型裁剪交付）和 P4b（选设备类型，依赖 P3）。
- 推迟：P7a 数据资源包、P6b 路由解释、外部配置自动写入与还原、HA subscribe_entities 实验、按需下载摄像机组件。P5c 并入摄像机类型停用时再做。
- 装包级 Instruments 或 ETW 对照只用于 P2a、P2b、P3a、P3b 和摄像机停用，其他包用关闭后计数为零的定向断言。

## 界面

1. 保留全关现有的长按确认，以及撤销横幅 10 秒和 15 秒分档，不改成点击后行内确认。
2. 设备级高风险确认保持现有独立确认，不行内化，不可在功能管理里关闭。
3. 提醒分级：烟雾、燃气、漏水、门铃、错过的定时必须置顶。门窗、人体、门锁、震动在对应提醒开启时置顶。高功率和长开提醒要逐条处理。只有离线、低电量这类普通提醒可折叠并一键收起。
4. 状态文案不能说假话：点名不可用的平台，例如「米家暂不可用，部分设备暂无数据」。演示状态固定写「示例家庭，不会控制真实设备」，未连接写「还没连接家居平台」。详情可点击查看，键盘可达。
5. 安全相关开关不弱化：高风险控制开关写明门锁、阀门、加热并仍需确认；链接直控写明会跳过所有二次确认；米家登录保留「可能被限制」和「登录会过期」。
6. Classic 目前是默认主题，覆盖 macOS 14/15，代码 6618 行，快照 162 张。不先删除 Classic。先抽共享组件并让新面板在现有基础上落地，主题收敛放到最后，单独验证和决策。
7. Windows 面板第一阶段保持固定高度档，先对齐结构和文案，自适应高度只在 macOS 试行。
8. 功能行增加「不可用」状态，写清原因和解决办法。
9. WP2、WP3 按 review-ui.md 第 19 条拆分，每个工作包标注通道与高风险面。
