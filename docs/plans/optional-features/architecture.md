# MenuBarHome 可选功能架构 v2

基线为 `936b6f03`。本稿按编排者裁决修订，工作量与性能门槛均为实施估算。摄像机体积沿用 v1.3.0 产物的只读检查，性能收益待实测。

## 修订摘要

- 首次打开先选平台。未连接时由用户主动开始连接，设备类型选择可后交付。旧用户仍按原设置启动，身份不确定时兼容回退并重试。
- 裁剪分为设备可用集合与安全保留集。隐藏设备仍可触发已开启的提醒。所有设备写入由宿主重新验目标，手动平台场景和脚本保留并说明可能影响隐藏设备。
- 停用先检查定时、自动化、快捷动作等引用，明确暂停后才提交。关闭立即封住入口，等后台资源回收后显示完成。移除按对象清理本机配置，历史按原归属保留。
- H 表拆开共享契约和首个消费者、Windows TS 写入门和 Rust 可取消连接、首启平台和设备类型。摄像机助手继续随 App，运行回收与类型停用同包交付。

## A. 产品范围与首启

设置页面叫「功能管理」，使用「连接」「功能」「设备类型」。采用随 App 发布的内置实现、封闭清单与现有本端工厂。本轮范围为米家与 Home Assistant 连接、可选 AI／语音及相关后台功能、设备类型。键盘基础控制由宿主持续提供。第三方代码插件与插件市场不在范围内。

| 用户所见 | 代码身份及行为 |
| --- | --- |
| 连接 | 沿用 `HomeBackend`、`HomeBackendDescriptor`。米家按既有区域及账号归属区分连接，支持多账号。HA 沿用规范化端点作用域，维持单实例，换令牌保留原作用域。米家局域网优先是连接的传输选项。 |
| 功能 | `FeatureID`，含语音输入、AI 兜底、主动建议、伴生接入、自动化。实况是摄像机类型下按需启动的子功能。AI 服务商是推理配置，与家居连接分开。 |
| 设备类型 | `DeviceCategoryID`，从既有 `DeviceKind`、facet 和设备配置导出。按逻辑设备与独立服务控制形状归类，同一物理设备的灯和窗帘可独立选择。设备类型开关是显示与资源偏好，安全规则仍由宿主负责。 |

普通 ID 用清单映射的值类型，Swift 用枚举和穷尽 `switch`，TS 用字面量联合及 `satisfies Record<…>`。磁盘输入先验证再解析，集中检查唯一性、支持状态及依赖环。私有构造或品牌类型只保护安全对象，例如已校验端点、回收句柄及未来若引入的已验证数据资源。持久化意愿和迁移版本，运行状态、健康、引用和权限动态求值。

**首次打开。** 复用原有「连接米家」「连接 Home Assistant」表单，可先跳过、用离线示例，之后添加第二个平台。尚未选择并主动发起连接时，启动及唤醒不扫码、不探测 LAN、不登录、不轮询、不请求权限。HA 的发现与端点验证由用户在 HA 路径触发，保留原明文同意。现有 macOS 自动发现门位于 `Sources/MijiaCore/HomeStore.swift:1058–1068`、`Sources/MijiaCore/HomeStore+Backend.swift:1106–1114`，由 P4a 修改。引导保留填写内容和可重试错误，示例状态和真实连接互斥，退出示例后恢复用户原选择。

**随后选类型。** 推荐默认展示全部已支持类型，提供「自己选」和「只用灯和开关」预设，显示当前平台可用性。选择前说明「为了继续提供已开启的安全提醒，仍会读取部分隐藏设备」，并指向「安全与提醒」。实际裁剪只在明确保存选择、处理完引用影响后启用。完整预设随摄像机停用等类型切片就绪后开放。新安装的 AI、语音、伴生按需开启。已有引导接缝见 `Sources/MenuBarMijiaApp/OnboardingGuideView.swift:42,186,271`、`windows/src/ui/onboardingGuide.ts:341`。

## B. 启停、引用与升级

| 状态 | 用户可见及运行行为 |
| --- | --- |
| 可用（关） | 功能只在管理页出现。保留配置，后台无该功能的专属任务。 |
| 已启用（待用或运行） | 语音等用户按麦克风或专用键，摄像机等实际开流。启用的连接和规则依原调度运行。每个来源实例或功能持有独立代次及任务句柄。 |
| 不可用／运行失败 | 功能行显示原因及可行处理，如系统不支持、尚未授权、连接未配置。启动失败先释放部分资源，仅仍启用的运行项可退避重试。临时失联保留意愿和引用归属。 |
| 在用／停止中 | 关闭前展示引用影响和解决动作。接受关闭后立即封住入口，回收成功才显示已关闭。回收失败显示「停止中，可重试」。 |

**解析与关闭。** 清单只记录明确的硬依赖、启动与平台条件。运行时由宿主同时求出已配置集合和有效集合，显式停用及明确的未连接态不会被旧主源回退重开。关闭父项时预览受影响子项，确认后按逆依赖回收。语音转文字先进入原本地解析器，AI 兜底可独立关闭。历史记录、提醒评估和设备展示各有自己的消费者。

**引用判决。** 使用宿主未裁剪的身份索引，复用 `DevicePreferenceIndex` 的 ID 收集。按对象种类和稳定 ID 去重列出名称、类型与连接归属。区分可关闭、需暂停的引用、以及无法确定归属而须先处理的阻塞。临时离线可用最后可信的归属，解析失败时保留原条目并显示原因。预览与提交之间重读引用、对象及代次，影响变化时刷新预览。取消保留原选择。

- 等待定时、错过定时、外部来源定时、启用的自动化、快捷动作和被执行计划引用的设备群组均参与预检。关闭会影响既有计划时，显示具体条目，由用户选「暂停这些项并关闭」或「取消」。动态全关等规则按原作用范围检查，避免缩小目标后静默运行。未启用的规则保留，打开前重验。
- 暂停保留目标、来源戳、排程、原分区与用户设置，功能或连接再次开启时重验作用域及目标。恢复时已过期的定时进错过流程，原外源条目仍按 ADR-0019 范围重分区，继续使用现有手动执行、取消与锁屏守卫。跨 `await` 按 ID 重查并在同一无等待区间提交。关联多来源戳时按真实目标归属判断影响，无法确认时阻止本次变更。依据 `Sources/MijiaCore/AssistantSchedule.swift:173–183`、`Sources/MijiaCore/HomeStore+Assistant.swift:630–703,771,812–843`、`windows/src/core/scheduledCommands.ts:97–160`、`CODING_STANDARDS.md:41–46`、`docs/adr/0019-scheduled-command-source-scope.md:20–34`。
- 平台场景和脚本在所属连接生效时继续支持手动启动。裁剪态下提示「可能控制已隐藏的设备」，沿用原高风险确认判定。HA `HomeScene` 与合成路径没有可靠目标清单，本轮不做目标提取或按类型批量暂停场景栏。被本地定时、规则、快捷动作引用的场景仍按实际来源预检，平台自身独立运行的自动化由平台管理。依据 `Sources/MijiaCore/Models.swift:1589–1597`、`Sources/MijiaCore/DeviceSynthesizer.swift:479–514`。
- 收藏、排序、菜单栏偏好、别名与实况偏好等保留并在可用时按原 ID 恢复。固定来源暂不可用时保留固定关系，重绑由用户明确指定。避免把跨源别名、重新出现的设备或同名条目当成同一写入目标。

**回收顺序。** 预检并处理引用 → 单写者保存停用意愿及暂停状态，封住提交路径并推进代次 → 清该作用域的确认、草稿、撤销、缓存展示和导出 → 取消重试、扫描、识别、推理、上下游读与 OS 订阅，关闭连接、IPC 工作及子进程并等退出 → 回报完成。保留已发出写入的原回执与所有权规则，结果未知时禁止自动重发。共享的锁屏、提醒和系统监听仍由宿主持有，解绑停用功能的订阅。快速重新开启等待旧实例收完，并按当前意愿建立新实例。

**Windows 两段交付。** TS 先在所有正常请求入口封住新读、新写和重试，以 `SourceEpoch`、作用域代次及 `AbortController` 拦截迟到提交。原生任务尚未接入取消时，跟踪已发调用并等其退出，期间保持「停止中」。验收从停用生效起无该源新请求，停止完成后无存活请求。Rust 后续另一个 PR 新增宿主持有的启用状态与作用域代次登记，从显式启停／换端点接缝同步，只接受当前登记作用域和代次的 IPC，不以单次入站参数中的布尔为依据。取消必须能唤醒阻塞的连接或读，并在关闭完成前等待实际退出。macOS 复用 `shutdown` 和 `providerShutdownTask`。Windows 共享 1 秒 tick 分离可选分支，安全、撤销及定时仍按原调度和开关工作。依据 `Sources/MijiaCore/HomeStore+Backend.swift:112–133`、`Sources/MijiaCore/HomeProvider.swift:307–325`、`windows/src/ui/sourceEpoch.ts:68`、`windows/src/ui/appLifecycle.ts:1119–1168`、`windows/src-tauri/src/home_assistant.rs:240–277`。

**升级路径。** 优先读取已存在的设置和引导标记，区分原始键缺失、默认值和用户明确选择。凭据、账号、配对及本地数据只作辅助。先判断身份，再应用新装默认。旧用户沿用原解析结果和行为，含双源、主连接、演示、米家多账号、HA 明文同意、LG、历史功能开关及旧版默认可用能力。仅确认无持久痕迹时进入新装分支。身份读取失败或不确定时走旧启动逻辑，记录可重试原因，保持旧配置且不写迁移成功标记。依据 `Sources/MijiaCore/HomeStore.swift:985–999`、`Sources/MijiaCore/HomeStore+Onboarding.swift:13–25`、`windows/src/ui/settings.ts:133`。

- 新版记录先完整校验再提交，版本化、幂等，保留未知字段和已明确的选择，凭据槽、来源戳和定时存储沿用现有契约。提交中断可重试。降级兼容须验证旧版本无法执行新版暂停项，未验证前不承诺降级后仍能识别暂停。凭据槽见 `CODING_STANDARDS.md:33–37`，定时见 `CODING_STANDARDS.md:41–46`。
- macOS 双实例不作为支持场景。迁移和移除按短临界区读取最新记录、按字段及所有者版本合并、写回，后写者重读，记录脱敏的冲突/重试诊断。两个新版实例之间以本机存储写入互斥保护该区间，撤销完成等待放在锁外，返回后核对版本。并发修改同一对象时保留已提交结果并重新预检，禁止用旧缓存覆盖。移除中的实例保留停止标记，旧清理任务遇到所有者版本变化时停止，不能删除重绑的新槽。

## C. 停用与移除

| 对象 | 停用后的资源变化 | 移除的范围 |
| --- | --- | --- |
| 米家账号或 HA 连接 | 停掉该实例的云/LAN 请求、扫描、重试、写入及实况租约，其他连接继续工作。 | 预览并确认之后，按作用域清本机凭据槽、地址绑定、地址同意、会话／拓扑缓存及临时流密钥。共享项在最后一个使用者移除后清。历史、用户条目与必要的旧 ID 保留，远端授权由对应平台管理。 |
| 设备类型 | 从面板、搜索、AI、伴生目录与直接控制入口移出，释放专属资源，按 D 保留提醒评估。 | 可从已选类型移除并随时加回。设备在平台的注册、用户历史和偏好保留。 |
| AI、语音、建议及自动化 | 按功能分别释放请求、退避、音频、识别、订阅和专属定时。已请求的系统授权结果用代次校验，不在后台启动录音。 | AI 可单独移除选中服务商的本机配置及对应密钥槽。语音为系统能力，从已启用列表移除后停止申请权限并提供系统权限管理入口。自动化和排程仍可编辑或删除各自的用户条目。 |
| 伴生集成 | 作废集成令牌，取消待提交动作并停止导出、清除快照。 | 系统仍可能列出静态入口，已停用集成返回明确反馈。旧令牌不得降级为普通链接；用户独立启用的普通链接沿用现有策略。 |
| 摄像机 | 打开时才启流，普通隐藏沿用保温，显式停用立即取消准备、重试、帧、保温、子进程和 UDP。仅允许原会话发必要的关停请求。 | 通过摄像机类型管理运行与展示。助手继续随 App 提供。 |

连接移除采用可重试的清理记录。先提交带所有者版本的移除意愿，收完资源再分槽删除，完成前拒绝重启或重绑同一作用域，并在重启时续做。清理预览明确本机删除与保留的内容，诊断不记录秘密。macOS 多槽共用一个 Keychain item，读合并后只更新选中的槽。依据 `Sources/MijiaCore/CredentialVault.swift:22–39`、`windows/src-tauri/src/credentials.rs:1–5`、`docs/adr/0013-raycast-companion-contract.md:23–36`。

## D. 设备类型裁剪与控制边界

### 同一身份索引，两套消费集合

从原始拓扑建立轻量身份索引，保留规范 ID、来源归属、共享父实体、服务类别、隐藏／禁用标记和安全信号所需特征。先求读计划，再按原来源合成与去重规则生成两套集合。

| 集合 | 纳入条件与去向 |
| --- | --- |
| 设备可用集合 | 当前启用来源与所选类型的合格逻辑设备及独立服务。面板、搜索、AI 目录、伴生导出、建议、自动化编辑器的新目标及直接控制都从这里获取。保留属性依赖、共享父项和读回锁。 |
| 安全保留集 | 只要某项提醒开启，启用来源中能提供相应信号的对象仍读取并合成到可供评估的最小形状。包括传感器、门锁、阀门、插座和空调等实际信号来源。提供给提醒评估及其所需的状态历史、去抖、离线或长开时间基准。隐藏对象的提醒可显示名称、原因和信号，但不露出设备卡片或直接控制动作。 |

读计划取两套集合的必要读键、共享属性及仍有合法消费者的并集。明确无消费者的历史、查询或专属监听停止。关闭设备类型不会修改提醒设置，只有用户到「安全与提醒」关闭相应提醒后才撤掉它的独占读取。连接停用或暂不可用时，如实反映数据和提醒覆盖范围。当前评估遍历传入设备对象，仅保留属性键无法维持安全提醒。依据 `Sources/MijiaCore/HomeStore+Backend.swift:431–444`、`Sources/MijiaCore/SensorAlerts.swift:25–40`、`windows/src/ui/activityStackView.ts:1390–1414`。

- **米家。** 在 `propKeys`／`collectMiotPropKeys` 和 LAN/云端分流前删去关闭类型无消费者的键，跳过相应补充查询和专属合成。登录、拓扑、房间和规格索引的固定成本按实测保留。分类确凿且无消费者时可推迟完整规格读取，未知时按需只读识别。单源、双源与多账号共用计划。每账号每轮云端每 100 键一批，无 LAN 分流和失败重试时批数为 `ceil(K / 100)`，例如 500→200 键为 5→2 批，90→40 仍为一批。依据 `Sources/MijiaCore/MiCloud/MiCloudProvider.swift:603–620,684–741,1065–1076`、`Sources/MijiaCore/MiCloud/MiCloudClient.swift:222,790–799`、`windows/src/ui/cloudRefresh.ts:62–83,230–264,1176–1188`、`windows/src/core/miCloud/client.ts:671–675`。
- **HA。** macOS 继续全量拉取及订阅 `state_changed`，在本机对无消费者的实体跳过展开和合成，也不因此触发发布。Windows 保持原生拉取 registry 和状态的链路，先在 TS 跳过无消费者的状态展开和合成。两端 HA 链路级网络收益按 **0%** 验收，本轮不承诺 Windows IPC 字节下降。保留 registry 排除与 states fallback 去重，避免上游已隐藏或禁用的实体复现。独立推迟 `subscribe_entities` 实验。依据 `Sources/MijiaCore/HomeProvider.swift:612–623`、`Sources/MijiaCore/HAHomeSnapshot.swift:38–99`、`windows/src-tauri/src/home_assistant.rs:240–259`、`windows/src/core/homeAssistant.ts:1511–1517`、`CODING_STANDARDS.md:9–11`。
- **扫描。** 保留用户主动的只读扫描，仅扫描有效连接，可取消并按代次丢弃结果。诊断分别解释用户停用、连接不可用、上游隐藏或禁用及确实不支持，必要时按需读识别规格。依据 `Sources/MenuBarMijiaApp/UnsupportedDeviceScanner.swift:35–129`、`windows/src/core/diagnosticsAndScanner.ts:601`。

### 宿主写入门

面板、快捷动作、URL、伴生、语音、AI、自动化、定时与撤销的写入在宿主统一校验。派发前解析当前规范 ID、facet、连接路由及代次，弹出确认后也要复验。设备可用集合外的目标立即拒绝并零写入。身份索引确认目标仍存在且类型关了，返回「该设备类型已关闭」。找不到目标时返回「设备不存在」。已知连接不可用时点名该平台，歧义目标按冲突拒绝。两端的 `requiresConfirmation` 对未知对象返回 `false`，所以可用性判断必须发生在确认判定前。锁屏、现有确认和 URL 策略的合法例外都在目标校验之后执行，随后仍遵守乐观锁、撤销与写入所有权。

手动全关只纳入当前可用视图中按原全关策略计算的目标，明确提示范围，保留默认排除及 10 秒／15 秒撤销分档。定时、自动化和快捷动作须先核全体目标，禁止执行残缺计划。平台场景和脚本走 B 的手动规则。跨源映射保持原有路由和去重，无法证明同一身份且同一服务可用时拒绝，避免借切换来源绕过停用或确认。依据 `Sources/MijiaCore/ManualControlPolicy.swift:34–35`、`windows/src/core/assistant/actionPolicy.ts:404–406`、`Sources/MijiaCore/HomeStore+Undo.swift:327–355,903–959`、`windows/src/ui/commandDispatch.ts:1122–1130`。

### 定向计数与装包对照

每个切片验证晚到回调、快速反复切换、关后零新增工作和无越权写入。用假时钟、可控完成门及模拟写入，推进到原周期和最长退避之后，对受影响的任务、连接、请求、写入、监听和状态提交做定向计数。摄像机还跨越原 120 秒保温窗口观察，验证旧流和 UDP 清空以及重新打开只建一份实例。

装包级对照限 P2a、P2b、P3a、P3b 和摄像机停用的实际运行切片。macOS 用 Instruments 和进程／连接日志，Windows 用 ETW/WPR 和进程、IPC／网络计数。用脱敏回放固定拓扑、账号、状态帧与速率，比较全开、只用灯和开关、相关源停用。覆盖冷启动、面板打开和隐藏各 15 分钟、网络断连与恢复及一次睡眠恢复，每组至少三次取中位。报告键数、批次、字节、LAN 和连接请求、重试、合成次数及 p50/p95、CPU、内存和呈现卡片数。验收为达到读计划、正常刷新与控制无回归。回放可核对资源和零写入，真实设备只读复核，控制回归用模拟或隔离设备。

## F. 跨端契约与验收轨迹

- P1a 拟建 `Shared/capability-manifest.json`，只记录稳定 ID、类型、硬依赖、新装默认、启动策略、平台可用性和文档矩阵 ID。双端解析与门禁保持纯契约，默认值尚不写入运行设置。构建期检查唯一性、映射完备、依赖无环及意外默认变动。两份平台矩阵继续反映实际支持度，`supported` 指产品支持，授权与当前可用状态独立。依据 `docs/capabilities.json:5–52`、`scripts/check_capability_matrix.py:16–20,608–646`、`scripts/check.sh:269`。
- P1b 定义引用判决的输入输出以及 capability_selection_golden.json（拟建，放在 Tests/Fixtures），接入双端已有测试套件。两端判决引擎各随 P2a 的首个消费者交付，后续用同一机制补接 HA、设备类型和暂停恢复。共享输入覆盖旧版设置、来源与账号、引用图、读计划与事件时序，输出覆盖有效集合、引用归属、暂停与拒绝原因、原始目标与写入计数。分期时按 ADR-0006 明示未落地端和对应包，每一语义落地须跑对应端的共享用例，完成两端后同一组断言必须全绿。依据 `CODING_STANDARDS.md:33–39`。
- **固定断言一。** 关闭传感器类型并保留漏水提醒，漏水帧仍触发告警且置顶，传感器仅有告警评估所需数据，设备在卡片、搜索、AI 目录、伴生导出及直接控制入口均不可用。显式关闭对应提醒后其独占读和评估停止。
- **固定断言二。** 关闭类型后，旧 URL、AI／语音意图、定时和伴生请求指向已隐藏目标，返回「该设备类型已关闭」，写入计数为零。不存在的 ID 返回「设备不存在」。确认期间关闭、来源切换或旧回调晚到也零写入。关闭前仍须走原高风险确认与锁屏守卫。
- **固定断言三。** 裁剪态手动启动平台场景和脚本继续可用，提示可能控制已隐藏的设备，使用原安全与来源检查。受影响定时、启用自动化和快捷动作逐条列出，取消保持原态，确认暂停后原记录保留，恢复要重验且过期定时进入错过流程。
- 另覆盖迁移失败／重试、macOS 冲突后重读、其他账号保持在线、全关与撤销、防上游隐藏实体翻出、米家拆键、同一物理设备上的混合类型、动态自动化规则及 LG 例外。旧黄金语料守住存量无显式选择路径。

## G. AI、语音及外部接入

- AI 复用现有服务商 preset、自定义端点及本地模型。最多一个活动服务商，分开管理模型、端点同意与按 host 绑定的密钥槽。关闭或切换后取消请求、重试和迟到结果，基础键盘／本地解析、合法已存排程继续工作。关闭云端后不自动请求其他厂商。依据 `Sources/MijiaCore/AssistantConfig.swift:264`、`Sources/MijiaCore/AssistantLocalModel.swift:46–69`、`CODING_STANDARDS.md:30,37`。
- 语音入口先按现有系统支持状态决定可用性。macOS 取消音频 tap、识别及松手／静默定时器，Windows abort Web Speech，回收后只允许新代次启动。任何二次授权、权限和设备写入仍走现有规则。
- 借鉴 Magpie 的启用意愿、在用提示及逆序释放。Raycast、CLI、MCP 沿用现有伴生协议，提供复制配置、检测接入、断开，显示本机访问范围。集成共享令牌一并撤销，自动写入与还原外部配置延期。路由解释 P6b 延期，保留现有路由；同一写入结果未知时禁止自动跨源重发。依据 `magpie-live-notes.md:15–19`、`docs/adr/0013-raycast-companion-contract.md:14–36`。

### 总体执行顺序

批次是默认合入顺序。可并行表示相互独立的工作可同时实现，按仓库规则逐个合入。改同一端共享设置、生命周期或调度文件的包在对应批次内排队，若装包或 CI 出错先闭环。

| 批次 | 工作包与并行安排 |
| --- | --- |
| 第 0 批 | P0a、P0b、P1a 可并行。 |
| 第 1 批 | P1b。 |
| 第 2 批 | P2a-M 与 P2a-W 并行。 |
| 第 3 批 | P2b-M 与 P2b-W 并行，各自复用同端 P2a 已合入的启用输入。 |
| 第 4 批 | P4a-M、P4a-W 与 P2b-R 可并行，TS 首启不依赖 Rust 登记。Rust 的 TS 接缝在 P4a-W 合入后联调。优先完成首启平台选择。 |
| 第 5 批 | 两端并行，每端依次做 P2c、P3a、P5a。 |
| 第 6 批 | 两端并行；各端依次做 P3b、P3c、P5b。 |
| 第 7 批 | 两端并行；各端依次交付 P3c 摄像机包、P4b、P5d-A。 |
| 第 8 批 | 两端并行；各端依次做 P5d-T、P6a。 |
| 第 9 批 | P8。 |

P6b 路由解释、P7a 数据资源包、运行时上游下载及任意路径治理、HA 订阅实验、外部配置写入及还原、摄像机按需下载均在本轮之外。
